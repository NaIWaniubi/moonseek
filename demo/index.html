这个索引是什么

mooncakes.io 上全部 3,698 个已发布包的实时注册表数据：包名、作者自填关键词、描述、依赖边。

索引由 原生 MoonBit 构建成 MSK3 快照（1.3 MB），再由 浏览器里的 wasm-gc 直接加载——同一份字节格式，两个后端。

没有任何 JS 搜索逻辑：分词、倒排、BM25、高亮、拼写纠正全部在 MoonBit 里。

查询语法

词项 全文匹配
"短语" 精确短语（位置校验）
"a b"~3 松散短语：允许 3 个词间隔
A AND B / A OR B
A NOT B 排除
title:词 字段限定
前缀* 字典序展开
(A OR B) C 分组
中文按重叠二元切分，零词典

为什么不是 LIKE '%x%'

名字子串搜索（title-only 配置）在这 17 条查询上的 NDCG@10 是 0.408；完整索引是 0.905。

差别来自：关键词字段、描述正文、依赖边，以及 BM25 的 tf 饱和与长度归一。

把 .txt / .md / .json / .csv 拖进来，浏览器内即时建索引。文件不会离开这台机器—— 没有任何网络请求，解析、分词、索引、搜索全在这个页面的 wasm 里完成。

持久化

“保存快照”会把整个索引序列化成 MSK3 字节并 base64 编码，写进 IndexedDB。 刷新页面后“从本地存储恢复”直接读回——不需要重新解析任何文件。

同一个字节格式也能被原生 CLI 读取，所以索引可以跨进程、跨后端搬运。

同一份 3,698 包语料、同一 17 条查询，只改字段权重与索引范围。数字由 tools/eval 在原生构建上生成，可复现。 标签是从语料结构派生的（作者自填关键词 / 依赖边 / 包名），不是人工标注——报告里已明确说明这一点。
