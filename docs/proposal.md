# moonseek 项目申报书

**1、项目名称**

moonseek —— 纯 MoonBit 全文搜索引擎、服务与分布式集群

**2、项目简介**

moonseek 是一个完全用 MoonBit 编写的搜索引擎：既是可嵌入的库，也是可独立运行的服务，还是可水平扩展的集群。纯 MoonBit 核心零 FFI，编译到 native / WebAssembly / JavaScript；一个二进制按参数即可作为单机节点、**分片**或**协调器**运行。能力涵盖倒排索引与 BM25、精确与松散短语、免词典中文分词、模糊纠错、分面与数值聚合、**HNSW 向量检索与 BM25×向量混合排序**、HTTP 检索服务、以及**一致性哈希分片、写入复制、跨分片聚合、在线扩容与副本修复**与全局一致评分、故障转移。已发布 mooncakes v1.0.0（325 项测试全绿、native `--deny-warn` 零告警；CI 十矩阵含质量回归、跨目标快照互通、集群与复制两份端到端校验），并有在线演示：**浏览器里直接搜索 mooncakes 全部 3,698 个真实包**。

**分布式正确性实测**：3 分片 vs 单机同语料，全局统计模式（`?dfs=true`）下 **8/8 查询排序逐位一致、最坏逐条分数差 0.000e+0**（p50 单机 5.3 ms / 三片 5.8 ms；两阶段全局统计 9.5 ms）。**一致哈希对账**：3→4 片时哈希环只搬 **24.2%** 文档，取模分片搬 **74.9%**（理论最优 25%），且分片负载 969/1024/1007 均衡。**复制实测**：3 000 篇**经协调器写入**，6/6 个成员（主+副本）全部落盘，杀掉主分片后结果逐字节不变；整组失效则精确上报 `ok=2, failed=1`。**在线扩容实测**：3 000 篇、3→4 片，规划器预测搬 762 篇（25.4%），执行器搬 762 篇，四片最终 840/738/660/762，与预测分布**逐项相同**，总量仍是 3000（不丢不重）；搬完后 `_plan` 报 0，重跑为空操作。**副本修复实测**：某副本在写入期间掉线（应答如实报 5/6 而非成功），回来后 `_repair` 精确补齐 1007 篇；直接塞进副本的脏文档被下一次 repair 删除；随后杀掉主分片，集群答案逐字节不变。**向量召回率对账**：HNSW vs 暴力搜索，ef=32 达 0.996、ef=64 达 0.999。

**检索质量可复现**：`tools/eval` 在全量注册表上算 NDCG@10 / MRR@10 / Recall@20，产出 `docs/quality.md` 与消融表——字段加权 0.9045、等权重 0.8236、只搜包名 0.4082（加权比子串搜索高 122%）；长度归一在该语料为 −1.1%，报告如实写出。标注由语料结构派生，与检索器输出无关；报告声明其不可与 BEIR/MS MARCO 相比。

**3、项目方向，通用性说明**

方向：数据处理与数据库 / 基础工具库（填补 MoonBit 生态在全文检索基础设施上的空白）。

通用性：moonseek 不绑定任何应用场景或数据格式——检索能力以通用库 API 暴露（Index 建索引、Document 加文档、Query 查询语法、FacetFilter 过滤、Snapshot 序列化），字段模式由调用方声明。因此同一个库既能做服务端文档检索，也能做浏览器端离线搜索、本地知识库、代码检索或 RAG 召回底座；核心不依赖文件系统与网络（native 文件层单独可选），可被任意 MoonBit 项目作为依赖复用。

**4、至少 3 个完整的预期使用场景**

- **场景一：服务端文档检索（已落地）**。`moonseek-server` 可直接部署：批量灌文档、检索（分面过滤 / 数值聚合 / 高亮片段 / 打分解释）、拼写纠错、词项统计；索引以带 CRC 快照落盘，WAL 保证崩溃不丢数据。仓库内 `console/` 是驱动它的 Web 控制台。
- **场景二：浏览器端零后端搜索（已完整落地）**。`demo/` 索引 **mooncakes.io 上全部 3,698 个已发布包**的包名、关键词、描述与依赖边；索引由**原生二进制**构建为 1.37 MB 快照，再由**浏览器 wasm-gc** 直接加载——同一份字节跨两个后端。实测快照加载 ~200 ms、中位查询 **0.20 ms**、wasm 二进制 206 KB；同页可拖入自有文件即时建索引，并持久化到 IndexedDB 供刷新后免解析恢复。
- **场景三：本地笔记与代码检索工具**。CLI 把笔记目录或代码库索引到本地快照，native 直接读写文件；写入先落 WAL，异常退出后重放恢复；索引损坏可检测并拒绝加载，而非静默返回错误结果。仓库内 `tools/registry` 就是这一路径的真实用例。
- **场景四：横向扩展（已落地）**。按 id 做**一致性哈希**分片（128 虚拟节点），协调器不持有数据，查询并行扇出后归并；写入按归属路由并**复制到该组每个成员**，因此副本真的能接管；需要与单机一致的排序时开两阶段全局统计，需要容错时配副本。缩容扩容前可用 `GET /_plan?shards=N` 按真实文档 id 算出要搬多少。扩容时先跑 `GET /_plan?shards=N` 拿到「要搬多少」，再 `POST /_rebalance?from=N` 原地搬（先写目的、全组确认后才删源）；副本掉线回来后 `POST /_repair` 与主对齐。可同时跑多个协调器（它们不持有状态）。CI 真起三片/三主三副/四片扩容，跑通「排序一致 / 聚合等于单机 / 复制后故障转移 / 扩容后仍等于单机 / 修复后接管无感」。
- **场景五（延伸）：AI 应用的检索底座**。BM25 与向量检索同进程融合（RRF 或加权，返回每条命中在两个榜单的名次），可先按字段/分面过滤缩小候选，再给出可解释的候选（逐词项 tf/df/idf 可分解），直接充当 RAG 第一级召回，无需外部向量库。

**5、拟实现的核心功能**

已完成：倒排索引与多字段加权；BM25（k1/b 可配）；CJK 二元切分；布尔 / 精确短语 / 松散短语（`"a b"~N`，最小跨度算法）/ 前缀 / 字段限定；模糊搜索（编辑距离 + BK-tree，2.4 万词项提速 17–491×）；拼写纠错；分面过滤与计数；数值聚合（terms / stats / histogram / percentiles）；高亮与片段；逐词项打分解释；排序控制与游标分页；段式索引；WAL 崩溃恢复；CRC 快照（MSK3）；HNSW 向量检索与混合融合；HTTP 检索服务与 Web 控制台；**一致性哈希环与再平衡测算**；**分布式分片 / 协调器 / 写入复制 / 故障转移**；**跨分片分面与聚合（与单机逐项一致）**；**跨分片排序（score/id/数值字段，18/18 与单机一致）**；**在线扩容执行器（`_plan` 预测 = `_rebalance` 实际）**；**副本修复（双向）**；**多协调器**；CLI 与浏览器演示。

**6、是否为原创项目、移植项目或参考已有开源项目**

原创项目，非移植。未复制任何第三方实现；算法（BM25、CJK bigram、BK-tree、WAL 帧格式、FNV-1a+fmix32 哈希、HNSW、RRF）为公开文献的独立实现，代码全部自行编写。

**7、如为移植项目，需说明参考项目名称、来源链接和许可证**

不适用（原创项目）。项目依赖仅两个，均为 Apache-2.0 且仅使用未修改的公开 API：`moonbitlang/core`（标准库）、`moonbitlang/async`（仅用于 native 层文件与网络）。项目自身以 Apache-2.0 开源。
